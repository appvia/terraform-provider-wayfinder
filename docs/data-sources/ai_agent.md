# wayfinder_ai_agent (Data Source)

AIAgent is a configured AI agent: the instructions it works to, the models it may run on, the tools and MCP servers it can call, and the durable memories it keeps between runs. Starting a conversation with an agent is how AI-powered work is done in Wayfinder, whether that is the general assistant answering a question or a specialised agent authoring and testing a resource plan.

Wayfinder ships a set of built-in agents, referenced as "wayfinder/NAME". A tenant can also define its own, at tenant, workspace or environment scope, and reference those by name.

## Example Usage

```terraform
// Code generated by tfgen. DO NOT EDIT.

  name = "example"
  workspace = "example"
}
```

<a id="nestedatt--default_model"></a>
### Nested Schema for `default_model`

Read-Only:

- `disable_prompt_caching` (Boolean) DisablePromptCaching turns off provider-side prompt caching for this agent.

Caching is on by default: the large context an agent repeats across turns — its tools and system prompt, then the conversation tail — is read back at a fraction of the input-token cost, which is almost always what you want. Turn it off only if you have a reason to. Anthropic dialect only, including its Bedrock, Vertex and Foundry backends; ignored by dialects that do not support it.
- `effort` (String) Effort is how hard the model should think before answering, from "none" for a straight answer through to "max" for the deepest reasoning.

It says what you want, not how to ask for it: models express reasoning depth differently — some take a level, older ones take a number of tokens — and the provider's catalogue translates this into whatever its model expects. That is what lets the same agent run on any of them. A level the model cannot reach is clamped to the nearest it can, so asking for more than a model offers is never an error.

Leave it unset to use the default the provider records for the model.

- `none`: Answers directly, without reasoning first.

- `low`: Does a little reasoning — for short, scoped tasks where speed matters more than depth.

- `medium`: Balances reasoning depth against time and cost.

- `high`: Reasons thoroughly — the right default for work where the answer's quality matters.

- `xhigh`: Reasons harder than high, for demanding coding and agentic work on models that offer the level.

- `max`: Reasons as deeply as the model can, for problems where correctness matters more than what it costs.
- `model` (String) Model names one model at one provider, as "<provider>:<model>" — for example "anthropic:haiku-4.5". The model part is the provider's portable model name, not an upstream model identifier.

A plain name looks for a provider of that name belonging to your tenant, and falls back to the Wayfinder-provided provider of the same name when you have defined none. So an agent shipped naming "anthropic:haiku-4.5" runs on Wayfinder's inference until you define your own "anthropic" provider offering that model, at which point it runs on yours instead.

Prefix the provider to pin it: "wayfinder/anthropic:haiku-4.5" always means Wayfinder's own, "myworkspace/gateway:haiku-4.5" a workspace-scoped one.
- `model_parameters` (Map of String) ModelParameters are the parameters to use for this model. Keys and values are provider-specific.

### Nested Schema for `memories`

Read-Only:

- `access` (String) Access is how much of the store this agent gets: Write to record into it, Read to consult it without being able to change it. Defaults to Read, so an agent that does not ask to write cannot.

- `Read`: Mounts the memory read-only. An agent that only needs to consult prior notes should be given this: it cannot then corrupt a ledger another agent maintains.

- `Write`: Mounts the memory writable, so the agent can record what it learned for the next run.
- `name` (String) Name is the store's name, and the directory the agent sees it at — "run-ledger" is mounted at /memory/run-ledger. Two agents naming the same store at the same scope share it.
- `scope` (String) Scope is the level the store is kept at, relative to where the agent runs: Tenant for one store shared everywhere, Workspace for one per workspace, Environment for one per environment. Defaults to Tenant.

A store kept per workspace or per environment needs spec.applicableScopes to include workspace or environment — otherwise every conversation with this agent is at the tenant, where the store has no home.

- `Tenant`: Keeps one memory for the whole tenant, shared by every conversation with this agent wherever it runs.

- `Workspace`: Keeps a separate memory per workspace, so what an agent learns about one workspace is not mixed with another. The agent must require a workspace (spec.scopeConfig.requireWorkspace).

- `Environment`: Keeps a separate memory per environment. The agent must require an environment (spec.scopeConfig.requireEnvironment).

- `path` (String) Path is the repository-relative path to write the file to. Supports Go text/template expansion against the sourceContext — e.g. "{{ if .subdirectory }}{{ .subdirectory }}/{{ end }}Wayfinder.yaml". After rendering, the path is re-checked against the conversation's subdirectory sandbox: it may not be absolute and may not escape the subdirectory root via ".." segments.




<a id="nestedatt--sandbox"></a>
### Nested Schema for `sandbox`

Read-Only:

- `direct_cloud_access` (Boolean) DirectCloudAccess states that this agent wields cloud credentials itself: the cloud CLIs on its machine run as the external identities it is granted, rather than Wayfinder using an identity on the agent's behalf.

Every external identity granted "directaccess" to this agent at the tenant, at the conversation's workspace or at its environment is written onto the machine as a profile named after that identity. An agent that sets this and is granted none of them where a conversation is being started is refused when it is created, rather than failing on the first cloud command it runs.
- `egress` (Attributes) Egress is what this agent's machine may reach on the network. Left out, it reaches what Wayfinder allows every sandbox. (see [below for nested schema](#nestedatt--sandbox--egress))
- `enabled` (Boolean) Enabled gives this agent a sandbox. When false, the rest of this is ignored and the agent has no machine.
- `full_control` (Boolean) FullControl gives this agent administrator access inside its own sandbox: it can install system packages with `sudo apt-get install`, and build and run containers with `docker build`, `docker run` and `docker compose`. On a resumable sandbox what it installs and the images it pulls and builds are kept with its files. The sandbox is still a dedicated virtual machine, and it still reaches only the hosts it is allowed. Leave it off for an agent that only runs commands: its sandbox then starts with fewer permissions. Full control does not change the sandbox's size: one that runs docker usually needs a larger size than the default. Where full control is not available, an agent asking for it is refused.
- `persistence` (String) Persistence is whether the files this agent writes on its machine are still there after a break. Required when the sandbox is enabled.

oneTime keeps nothing: after a break the next command runs on a new, empty machine and the agent is told its files have gone. It starts faster and costs nothing while unused. Right for workflow tasks and agents that finish in one go.

resumable keeps the agent's working files through a break, so an agent picked up again finds its clones, installed packages and work in progress where it left them. Starting again takes a little longer, and the files are kept for a day after the conversation was last used, then removed. Right for conversations a person comes back to.

- `oneTime`: Keeps nothing through a break.

- `resumable`: Keeps the agent's working files through a break.
- `size` (String) Size is how much CPU, memory and disk this agent's machine is given, by name: one of the sizes Wayfinder offers, e.g. "S", "M" or "L". Leave it empty for the smallest, S, which is right for an agent that runs wf commands, git, kubectl, the cloud CLIs and small tofu plans. Choose M for large repositories, tofu plans over large stacks, and npm or go builds; L for docker builds, test suites and heavy compiles. An agent with full control that builds or runs containers usually wants M or L, though a single light `docker run` fits in S. A command that needs more memory than its size gives is stopped, and the agent is told why.
- `storage` (String) Storage is how much a resumable sandbox keeps for this agent, as a size such as "10Gi": its working files and, with full control, what it installs and the container images it pulls and builds. Leave it empty for Wayfinder's default of 5Gi; at most 20Gi. Only a resumable sandbox can be given storage.

<a id="nestedatt--sandbox--egress"></a>
### Nested Schema for `sandbox.egress`

Read-Only:

- `allow` (List of String) Allow lists the hosts the machine may reach over HTTPS and HTTP, e.g. registry.npmjs.org. A name starting with "*." covers that domain and every name under it, so *.example.com covers example.com and api.example.com. Addresses and ports cannot be allowed: only HTTPS on port 443 and HTTP on port 80 leave the machine.
- `replace_defaults` (Boolean) ReplaceDefaults makes Allow the whole of what the machine may reach, besides Wayfinder itself, in place of the hosts Wayfinder allows every sandbox. Set it for an agent whose work needs only a few known hosts, so that nothing else it is talked into can reach anywhere. Defaults to false: Allow adds to those hosts.



<a id="nestedatt--source_requirements"></a>
### Nested Schema for `source_requirements`

Read-Only:

- `require_source_access` (String) RequireSourceAccess states the least repository access a conversation must be given for this agent to be able to do its job, so an agent that exists to change a repository says so up front instead of failing partway through with a refusal the user cannot act on.

It is a MINIMUM on a ladder: "propose" is satisfied by a context that may also change workflows, and "proposeWorkflows" is what an agent that sets up or repairs CI should state. Setting it implies requireSourceContext — there is no way to satisfy a repository access requirement without a repository — so an agent need not set both.

- `read`: Reads the repository and changes nothing.

- `propose`: Additionally commits to a fresh branch and opens a pull request — a source context whose propose is set.

- `proposeWorkflows`: Additionally changes CI workflow definitions — a source context whose propose sets allowWorkflows.
- `require_source_context` (Boolean) RequireSourceContext indicates conversations must specify a sourceContext. When true, creating a conversation without spec.sourceContext is rejected. Defaults to false.
