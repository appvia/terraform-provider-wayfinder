# wayfinder_ai_context (Data Source)

AIContext is a piece of reusable background knowledge you write once and give to AI agents: your own standards, conventions and hard-won details that an agent could not work out for itself. It is markdown you author, plus the kinds of resource it applies to and, where relevant, which cloud it is specific to.

A context marked "Always" is given to every conversation about a resource of one of its kinds — a conversation with the assistant about a CloudResourcePlan, say, or with one of your agents about the resource it relates to — when its cloud matches. Wayfinder adds it, and nobody starting the conversation can leave it out. A conversation that is given a context starts with its whole body already in the agent's instructions, pinned at the version given, so what the agent was told does not change under it if the context is later edited. Contexts can be held at tenant, workspace or environment scope, so a team can add its own on top of the tenant's. The UI calls them "Agent Context".

A context is the opposite of a memory: you write a context and give it to an agent; an agent writes a memory for itself.

### Read-Only

- `annotations` (Map of String)
- `cloud` (String) Cloud optionally scopes this context to one cloud provider. When set, the context applies only to a conversation about a resource for that cloud, such as a CloudResourcePlan whose cloud is "aws". A resource with no cloud of its own is given the context whatever it says here.
- `description` (String) Description is a short summary of what this context provides, e.g. "Our naming and tagging standards for AWS". It is shown beside the name in lists, so you can see what a context is for without opening it.
- `for_kinds` (List of String) ForKinds lists the kinds of resource this context applies to, such as "CloudResourcePlan" or "KubeResourcePlan". A conversation about a resource of one of these kinds, with the assistant or with any agent, is given the context when its use is "Always". Only list a kind the whole body is genuinely useful for — a context has one body, not a section per kind. Each entry must be a kind of resource you write as configuration.
- `id` (String) The ID of this resource.
- `labels` (Map of String)
- `markdown` (String) Markdown is the body of the context. When a conversation is given the context, the whole body is added to the agent's instructions as the conversation starts.
- `status` (Attributes) (see [below for nested schema](#nestedatt--status))
- `status_json` (String)
- `use` (String) Use declares how readily this context is applied. "Always" gives it to every conversation about a resource of one of its kinds. "ByDefault" and "WhenChosen" are only offered where a person picks contexts for a run, such as the plan tester, pre-selected or not. An unset or unrecognised value is treated as "WhenChosen", so a context is never silently made mandatory.

- `Always`: Means the context is given to every conversation about a resource of one of its kinds, and cannot be left out.

- `ByDefault`: Means the context is pre-selected where a person picks contexts for a run, such as the plan tester, and can be deselected there. It is never given to a conversation automatically.

- `WhenChosen`: Means the context is given only when a person picks it for a run, such as the plan tester. This is also what an unset or unrecognised value means.
