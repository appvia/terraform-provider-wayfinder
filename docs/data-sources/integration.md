# wayfinder_integration (Data Source)

Integration represents an activated integration in your tenant. There are two kinds:

  - Feature integrations (e.g. ai, github, terraform) are Wayfinder-provided
    capabilities. Enable one to make its functionality available in your tenant.
    Some extensible feature integrations (e.g. http) also allow you to attach your
    own MCP servers, webhooks, and web APIs to them.
  - Custom integrations are ones you create and own. Your MCP servers, webhooks,
    and web APIs belong to a custom integration, which groups them and gives them
    context.

- `status` (Attributes) (see [below for nested schema](#nestedatt--status))
- `status_json` (String)
- `template_ref` (String) TemplateRef links a custom integration to the catalogue template it was created from, e.g. "wayfinder.dns@7", and records the template version you are on so an upgrade can be offered. It appears only on custom integrations created from a template: a custom created from scratch has none, and a feature integration never carries one (a feature is enabled, not created from a template). Set by Wayfinder; read-only.
- `type` (String) Type indicates whether this is a Wayfinder-provided feature integration or one you own. It is the integration's identity: "feature" is stamped by Wayfinder when you enable a catalogue feature; integrations you create are always "custom". Set by Wayfinder; read-only. You cannot create a feature integration yourself, and the type cannot change once set.

- `feature`: Is a Wayfinder-provided capability you enable or disable for your tenant, e.g. ai, github, or terraform.

- `custom`: Is an integration you own. Your MCP servers, webhooks, and web APIs belong to this integration.
