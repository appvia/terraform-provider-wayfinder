# wayfinder_web_api (Resource)

WebAPI is an outbound HTTP API you can call from Wayfinder: a reusable connection to a third-party system (base URL, credential and default headers) plus a set of templated operations Wayfinder invokes against it. It is the outbound counterpart of the inbound Webhook. Each operation call produces a WebAPIInvocation recording the request sent and the response received.

### Nested Schema for `spec_connection`

Optional:

- `auth` (Attributes) Auth is the credential presented on each request. Leave it unset for a service that needs none. (see [below for nested schema](#nestedatt--spec_connection--auth))
- `base_url` (String) BaseURL is the address requests are sent to, e.g. "https://api.example.com". It carries the scheme and host; what follows is the caller's — a WebAPI appends each operation's path, an MCP appends its own spec.path.

It may be a literal, or an expression over the inputs the object declares, e.g. "https://api.${{ .Inputs.site }}". An expression lets one shipped definition serve every tenant, each supplying its own value.

Required before the object may be enabled; one you have not finished configuring may leave it blank until then.
- `headers` (Map of String) Headers are sent on every request, in addition to anything an individual operation adds. Values may be literals or expressions over the declared inputs. Do not set a credential header here — Auth applies the credential by its type, and a header set by hand bypasses that.

On an MCP a value may also read the arguments of the tool call it is sent with, as "${{ .Args.<name> }}", so one registration serves every repository or project an agent asks about instead of one per value. GitHub's hosted Actions server wants "Mcp-Param-owner" and "Mcp-Param-repo" that way: with "${{ .Args.owner }}" the agent passes owner and repo in the tool call, as the tool's own schema asks, and the call works. A header reading an argument the call did not carry is left off, so the server answers saying which value it wanted rather than acting on a blank one. A WebAPI has no such arguments and refuses the expression.

### Nested Schema for `spec_connection.auth`

Optional:

- `access` (String) Access is the most an MCP's calls may do in the repository CodeRepoRef names: "read" (the default) or "write". A call is made at the highest level up to this that the conversation asked for and its agent holds. A web API takes the level from each operation's method instead — "read" for GET and HEAD, "write" otherwise — and refuses this field.

- `read`: Clones and fetches the repository and reads its CI results — which workflow run failed, which check is red, and what has been deployed.

- `write`: Additionally pushes branches, opens pull requests and comments on them.
- `code_repo_ref` (String) CodeRepoRef names the repository each call works on. Requests are authenticated with a short-lived token that Wayfinder mints for that repository alone, through the App it holds for the repository's provider. No secret is stored. Mutually exclusive with ExternalIdentityRef.

It is always a whole-field "${{ .Inputs.<name> }}" expression naming an input of kind CodeRepo, e.g. "${{ .Inputs.codeRepo }}", never a literal, so the repository is chosen by whatever uses the connection: an AI conversation answers it with the repository in its source context, and a web API invocation with one of its inputs. A call is refused unless the user, agent or workflow it is made for holds the access it needs in the repository's usableBy. Only GitHub repositories are supported.
- `external_identity_ref` (String) ExternalIdentityRef names the ExternalIdentity whose credential authenticates the outbound calls. It is a single self-describing reference ("name", "workspace/name" or "workspace/environment/name") to an endpoint-family identity: BasicAuth, TLSClientCert, BearerToken, APIKey or OAuth2ClientCredentials. The identity's service host must match the connection's base URL host, so a credential minted for one service is never presented to another. Mutually exclusive with CodeRepoRef.

An MCP may also name an AWS identity (AWSIAMRole or AWSIAMUserKey). An AWS identity is accepted only where the connection's base URL is AWS's own MCP server, https://aws-mcp.<region>.api.aws.

It may be a literal, or a whole-field "${{ .Inputs.<name> }}" expression naming an input the object declares. It may be nothing else: it names a Wayfinder object, so it has to resolve without running the call — that is what lets the identity be permission-checked when you save, and what keeps it visible to "what breaks if I delete this credential?".
- `github_org_ref` (String) GitHubOrgRef named the GitHub organisation a connection signed in to.

Deprecated: replaced by codeRepoRef. A connection that still sets it cannot be saved, and its calls are refused.

### Nested Schema for `operations.response.store`

Optional:

- `data_type` (String) DataType references the DataType resource whose schema validates the extracted Values. Its name — without any workspace prefix — is the key the data is stored under on the target resource. A bare name is the tenant's shared type, e.g. "incident"; "workspace/name" is one that workspace defined for itself, e.g. "team-a/incident". There is no fallback between the two, so a bare name always means the shared type. Only this web API's own workspace may be named: a tenant-scoped web API can use the shared types alone, and none can reach into another workspace. When set, Values must also be set (typed mode). When unset, the mode depends on Values: empty Values stores the response body verbatim (raw mode); non-empty Values extracts just those named fields with no schema (extraction-only mode).
- `items_to_parse` (String) ItemsToParse, when set, is a JQ expression yielding an array within the response, e.g. `.body.projects` for an endpoint that returns one entry per service. The store is then applied once per element, with the element exposed as `.item`, so a single call can write to many resources. Leave it empty when the response describes a single thing.

A polled endpoint nearly always returns a collection, so this is how a scheduled call spreads its results across the resources they belong to.
- `resource` (Attributes) Resource selects which Wayfinder resource(s) the extracted data is stored against, by matching values pulled out of the response.

Leave it unset for a call made in the context of something — a workflow step or a stack hook — where the data belongs to whatever triggered it. Set it for a call with no such context, above all a scheduled one: the data belongs to the resource it is *about*, not to the WebAPI that fetched it, and nothing else can work that out. (see [below for nested schema](#nestedatt--operations--response--store--resource))
- `values` (Map of String) Values is a map of output-field name → JQ expression, e.g. {"issueNumber": ".body.number"}, evaluated against the response context (`.statusCode`, `.body`, `.headers`) to build the object of extracted fields. Required when DataType is set (typed, validated). Optional when DataType is empty: set it to expose named fields without a schema, or leave it empty to store the whole body (raw mode).
