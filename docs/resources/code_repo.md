# wayfinder_code_repo (Resource)

CodeRepo is a catalogue entry for a single source code repository that Wayfinder can reach, naming the repository and the source control connection it is reached through. Registering a repository as a CodeRepo checks once that Wayfinder really can reach it, and gives other resources — such as a SourceProposal — a stable name to refer to it by, so they do not each have to repeat the connection details. A CodeRepo records what the repository is and whether it is still reachable; it does not itself change anything in the repository.

A repository is owned by exactly one workspace, which is required: there is no tenant-level repository. To let another workspace use it, grant that workspace in spec.usableBy — the repository stays where it is, and anything in the other workspace names it as GitHub does, "github.com/OWNER/REPO".

### Nested Schema for `usable_by`

Required:

- `access` (String) Access is how far this grantee may go: "read" to clone and fetch, "write" to also push and open pull requests, or "write-workflows" to also change CI workflow definitions.

- `read`: Clones and fetches the repository and reads its CI results — which workflow run failed, which check is red, and what has been deployed.

- `write`: Additionally pushes branches, opens pull requests and comments on them.

- `write-workflows`: Additionally pushes changes to CI workflow definitions under .github/workflows, which GitHub refuses at "write" alone. It is a level of its own because such a push changes what CI runs — on a self-hosted runner, what runs on your own machines.

Optional:

- `role` (Attributes) Role grants access to any subject holding a Wayfinder role at a scope, evaluated from the roles the caller holds at the time of the request. Name the workspace those holders must hold the role in — "*" for every workspace, e.g. `{role: workspace.member, workspace: "*"}` to offer a template to the whole tenant — or set tenant to grant to holders of a tenant-level role. Leave the workspace out to grant only within the workspace that owns the repository. Exactly one of subject or role must be set. (see [below for nested schema](#nestedatt--usable_by--role))
- `subject` (Attributes) Subject is the user, service account, group, AI agent, workflow or webhook this grant is for. Exactly one of subject or role must be set. (see [below for nested schema](#nestedatt--usable_by--subject))
