# wayfinder_schedule (Resource)

Schedule runs one named action on a target resource, over and over, on an interval. Each time the interval elapses Wayfinder starts a run and records it.

You can write one directly — "call this operation every six hours" — and you can also get one for free: a resource that lists what it wants run repeatedly, such as a WebAPI's spec.schedules, has its Schedules maintained for it by the write. Those ones are read-only, and say so: change them where they are declared, and removing the declaration removes the Schedule.

Either way it is the same resource with the same behaviour. There is no second mechanism for a derived schedule, which is what stops the two drifting apart.

## Example Usage

```terraform

  name = "example"

    every_json = jsonencode({})
  }
  target = {
  }
}
```

### Nested Schema for `schedule`

Required:

- `every_json` (String) Every is how long to wait between runs, e.g. "15m", "1h" or "24h". Pick a value comfortably longer than the run itself takes, and be mindful of what is at the other end: a slow daily report does not want a five-minute interval. The first run happens as soon as the schedule is enabled, and each subsequent run is timed from the start of the previous one, so runs never overlap.

Optional:

- `inputs` (Attributes List) Inputs are the values to run with, validated against whatever the thing being run declares it accepts — for a WebAPI operation, its own inputs.

A scheduled run has nobody to ask, so anything the run needs has to be settled when the schedule is written: a query parameter, a lookback window, a page size. An operation that requires inputs cannot be scheduled without them. (see [below for nested schema](#nestedatt--schedule--inputs))
