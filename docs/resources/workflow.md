# wayfinder_workflow (Resource)

Workflow is a reusable template that defines a named set of triggers and the tasks to run when one of them fires. It is the durable definition you author and keep; firing one of its triggers produces a WorkflowInvocation, a single run of the workflow's tasks, which Wayfinder then drives to completion.

Tasks run in parallel by default and each may declare the tasks it depends on, so a workflow can fan out and join. A task calls an HTTP integration operation, holds a conversation with an AI agent, reads a source repository, or runs a Wayfinder CLI command server-side.

## Example Usage

```terraform
// Code generated by tfgen. DO NOT EDIT.
resource "wayfinder_workflow" "example" {
  name = "example"
  workspace = "example"
  tasks = {
    example = {
      action = "example"
    }
  }
}
```

### Nested Schema for `tasks`

Required:

- `action` (String) Action is the "<integration>/<type>/<...>" slash-path identifying the work to perform: the first segment names the owning integration, the second selects the kind of thing to run, and the rest names it. "<integration>/webapi/<webapi>/<operation>" runs an HTTP integration action; "ai/agent/<name>" runs a conversation with the named AIAgent, and its structured result becomes the task's output — name a tenant agent as "ai/agent/<name>" and one a workspace owns as "ai/agent/<workspace>/<name>" or "ai/agent/<workspace>/<environment>/<name>", where the workspace must be the workflow's own; "ai/agent/wayfinder/<name>" runs one of the agents Wayfinder ships, which any workflow may name; "wf/<command>/<subcommand>..." runs a Wayfinder CLI command server-side; "checkout/github.com/<owner>/<repo>" reads the named source repository into the run's files.

Optional:

- `ai` (Attributes) AI carries the settings that apply only to an "ai/agent" task: where the conversation is created, the source repository the agent works against, and the model and effort to run it on. Ignored by every other task type. (see [below for nested schema](#nestedatt--tasks--ai))
- `checkout` (Attributes) Checkout configures how much of a "checkout/github.com/<owner>/<repo>" task's repository to read — the ref and the subdirectory. Which repository is the action's own business. Rejected on any other action. (see [below for nested schema](#nestedatt--tasks--checkout))
- `continue_on_failure` (Boolean) ContinueOnFailure marks this task as best-effort: if it fails, the tasks that depend on it still run, and the run as a whole still succeeds. Use it for a step whose failure is not worth abandoning the rest of the workflow for — inviting a user, posting a notification, tagging a resource.

The failure is not hidden: the task still reports as Failed with its reason, the run's message names every tolerated failure, and a dependent task can see what happened via `${{ .Tasks.<name>.failed }}`, `.phase`, and `.error.*` — so it can react (report it, take the other path) rather than only carry on.
- `depends_on` (List of String) DependsOn lists the names of tasks that must succeed before this task is scheduled. A task whose dependencies are all skipped is skipped; a task that joins several branches runs as soon as its un-skipped dependencies succeed. A dependency that failed normally takes this task down with it, unless that dependency declared continueOnFailure.
- `inputs` (Attributes List) Inputs provides templated values for this task, resolved live at dispatch time against the run context (`.Inputs.*`, `.Tasks.<name>.output.*`). (see [below for nested schema](#nestedatt--tasks--inputs))
- `when` (String) When optionally gates whether this task runs: a `${{ }}` template expression evaluated against the run context just before the task would be dispatched. The task runs only when it renders to "true"; otherwise it is skipped (and tasks that depend solely on it are skipped in turn). Use it to run a task only in certain cases, for example only for a particular trigger (`${{ eq .Trigger.Name "nightly" }}`) or based on an upstream task's output.
- `with` (Map of String) With provides a "wf/..." task's command parameters as named fields — each key is one of the command's own flags (or the reserved "name"/"args" positionals), typed exactly as the CLI defines it, and validated against the CLI's command schema when the workflow is written. Values are templated like Inputs. Rejected on other task types, whose parameters are their Inputs.

### Nested Schema for `tasks.ai`

Optional:

- `effort` (String) Effort is how hard the model should think before answering in this task's conversation, overriding what its agent asks for: one of none, low, medium, high, xhigh or max. A level the model cannot reach is clamped to the nearest it can. It may be a `${{ }}` template, like the fields above.
- `model` (String) Model runs this task's conversation on a model other than the one its agent declares, named as "<provider>:<model>" — "anthropic:sonnet-5", say, for the one task in a workflow that needs the harder thinking. It may be a `${{ }}` template, e.g. "${{ .Config.model }}", so the choice can live in the workflow's own configuration.

- `source_context` (Attributes) SourceContext binds the conversation to a source repository, so the agent's file tools read and write that repository. Required when the agent declares requiresSourceContext. Whether the agent may propose a change is declared on the source context itself, not here. ### Nested Schema for `tasks.ai.source_context`

Required:

- `kind` (String) Kind identifies the source kind. Only "github" is meaningful for a workflow: a hands-off run has no client to serve a local filesystem.
- `repo` (String) Repo names the repository the agent reads from, as "github.com/OWNER/REPO", e.g. "github.com/appvia/wayfinder", or a ${{ }} template that renders to one.

Optional:

- `branch` (String) Branch is the branch to read from. Empty resolves the CodeRepo's default branch, the same way it does for an interactive conversation.
- `propose` (Attributes) Propose, when set, lets the task's agent change the repository: its file tools may write as well as read, and it may commit those changes and open a pull request. Its presence IS the grant, so a task that omits it dispatches an agent that can only read. (see [below for nested schema](#nestedatt--tasks--ai--source_context--propose))
- `subdirectory` (String) Subdirectory constrains the agent's file tools, and any file it proposes, to a subtree of the repository. Must be a clean relative path — no ".." components and no absolute path. Empty means the repository root.

<a id="nestedatt--tasks--ai--source_context--propose"></a>
### Nested Schema for `tasks.ai.source_context.propose`

Optional:

- `branch_prefix` (String) BranchPrefix is prepended to the name of the branch the agent's changes are committed to. Must be a clean relative path, and conventionally ends with "/" so the branches group under it — e.g. "wayfinder-ai/cost-control/". Empty uses Wayfinder's own default prefix.
- `follow_pull_request` (Boolean) FollowPullRequest keeps the task's agent available after it opens a pull request: someone commenting on that pull request, or reviewing it, puts the agent back to work on it. The agent reads the pull request itself and decides what to do — nothing anyone wrote there is passed to it. Without this the run ends at the pull request, and a review left on it reaches nobody.

The agent must declare spec.supportsFollowPullRequests.

### Nested Schema for `triggers`

Required:

- `name` (String) Name uniquely identifies the trigger within the workflow, e.g. "nightly". Any trigger starts a run of every task; a task selects a particular trigger by referencing this name in its when condition (`${{ eq .Trigger.Name "nightly" }}`). The run's inputs are also available to task templates keyed under this name as `.On.<name>.*`.

Optional:

- `event` (String) Event is the resource event that fires this trigger, e.g. "Created". Set it together with Resource.
- `manual` (Attributes) Manual declares this trigger as manually fireable, with an optional input schema validated against the run subresource's supplied inputs. (see [below for nested schema](#nestedatt--triggers--manual))
- `resource` (String) Resource is the kind of resource whose events fire this trigger, e.g. "StackInstance". Set it together with Event to fire the trigger automatically on a matching resource event.
- `when` (String) When is an optional condition gating the fire: a `${{ }}` template expression evaluated against the triggering resource. The trigger fires only when it renders to "true"; combine conditions with `and`/`or` in one expression, e.g. `${{ and (eq .Resource.spec.tier "prod") (ne .Resource.metadata.name "test") }}`.

A value naming an identity of any other type is refused when it is supplied, rather than failing when the call runs. Leaving it empty accepts any identity type that can authenticate an outbound call. It may be set only on type=externalidentity, and is refused on every other type.

- `min_items` (Number) MinItems is the minimum number of items in the variable if a list or map
- `min_length` (Number) MinLength is the minimum number or length of the variable if a string
- `minimum` (Number) Minimum is the minimum numerical value of the variable if a number/float
- `optional` (Boolean) Optional is true when no value need be supplied: the object declaring it can be saved, and switched on where it has a switch, without one. An unanswered optional value reads as its defaultValue when one is set, and as nothing otherwise. Whether whoever uses the object may supply it later is for that object to say.
- `pattern` (String) Pattern is the pattern of the variable if a string. For list(string) and map(string), this is applied to each individual value in the list or map.
- `ref_type` (Attributes) RefType describes that this value is a reference to another Wayfinder resource. When set, the value is validated to be the name of an existing resource of the given kind, optionally filtered by field constraints. (see [below for nested schema](#nestedatt--triggers--manual--inputs--ref_type))
- `repo_access` (String) RepoAccess is how much of the repository the agent needs: "read" to clone and read it, "propose" to also commit to a fresh branch and open a pull request, or "proposeWorkflows" to also change the repository's CI workflow definitions. When empty, Wayfinder uses "read". Whoever supplies a repository must themselves be granted at least this much of it, and so must the agent, or the conversation is refused when it is created. It may be set only on type=coderepo, and is refused on every other type.
- `repo_branch_prefix` (String) RepoBranchPrefix is prepended to the name of the branch the agent's changes are committed to, e.g. "wayfinder-ai/cost-control/". When empty, branches are prefixed "wayfinder-ai/". Set it so branch protection or CODEOWNERS rules in the repository match every branch this agent opens; whoever starts the conversation cannot change it. It may be set only on type=coderepo, and is refused on every other type.
- `required_keys` (List of String) RequiredKeys is the list of required keys for a map variable. Ignored for other types.
- `schema_json` (String) Schema provides additional guidance as to the shape of the value when type=json.
- `secret` (Boolean) Secret indicates if the value is a secret and should be protected
- `type` (String) Type is the type of the value

- `string`: Is a string type

- `number`: Is a number type (integer or floating point)

- `bool`: Is a boolean type

- `list(string)`: Is a list type of strings

- `list(number)`: Is a list type of numbers

- `list(bool)`: Is a list type of booleans

- `map(string)`: Is a map type of strings

- `map(number)`: Is a map type of numbers

- `map(bool)`: Is a map type of booleans

- `json`: Is an arbitrary JSON type, used to represent any complex input/output that isn't better represented by the other types. Note that no validation is possible for a plain JSON input.

- `externalidentity`: Is a reference to an ExternalIdentity, naming the credential an outbound call authenticates with. The value is the identity's name and the scope it lives at ("my-identity", "my-workspace/my-identity" or "my-workspace/my-env/my-identity"), never credential material itself. Supplying a value resolves it: the identity must exist, you must be allowed to use it for what is calling, and its own kind must be one the definition's identityTypes accepts. A value naming an identity that fails any of those is refused when it is supplied, rather than failing when the call runs. It may only be declared where a definition is able to load an identity. It is refused on a CloudResourcePlan's inputs and outputs, a KubeResourcePlan's inputs, a stack definition's vars, an IntegrationDefinition's paramDefs, and a repo template's inputs, all of which would otherwise receive the reference as a plain string.

- `coderepo`: Is a reference to a CodeRepo, naming the repository an AI agent works on. The value names the repository as its provider does, "github.com/OWNER/REPO" (e.g. "github.com/appvia/wayfinder"), never a URL or a git credential. Use it on an AI agent's input where the repository is not fixed when the agent is written: the input sets how much of the repository the agent needs (repoAccess) and the branch prefix for its changes (repoBranchPrefix), and whoever starts the conversation supplies the repository. The conversation's spec.sourceContext is built from the value they supply. Supplying a value resolves it: the repository must exist, and the grant in its usableBy must cover the access the input asks for. That grant is checked against the person supplying the repository, not against whoever wrote the agent. The agent is checked separately, against the same repository, when the conversation is created. It may only be declared where a definition is able to load a repository and check that grant. It is refused on a CloudResourcePlan's and a KubeResourcePlan's inputs and outputs, a stack definition's vars, an IntegrationDefinition's paramDefs, and a repo template's inputs: each of those passes its values through as text to Terraform, a Helm chart, a rendered manifest or a scaffolded file, where the reference is only a plain string and no grant over the repository is checked.
