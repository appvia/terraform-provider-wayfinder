# wayfinder_feature_integration (Resource)

Enables a built-in Wayfinder feature integration, such as `azure`, `github` or `ai`, at tenant scope. Use `wayfinder_integration` to create custom integrations instead. Enabling a feature is idempotent; applying after it is disabled outside Terraform re-enables it. Destroy disables the feature unless `keep_enabled_on_destroy` is true.

Feature integrations are built into Wayfinder, for example `aws`, `azure`, `gcp`, `github` and `ai`. You don't create them, you turn them on. This resource calls Wayfinder's enable action with the bare feature name, and Wayfinder stores the result as an integration named `wayfinder.<name>`. Custom integrations, built from your own templates, are managed with `wayfinder_integration` instead.

If someone disables the feature outside Terraform, the next plan shows an in-place update and the next apply enables it again.

## Parameters

Only the keys you set in `params` are managed. Keys set elsewhere, such as in the Wayfinder UI, are left alone. Removing a key from `params` deletes it from the feature in Wayfinder.

Each value is a JSON document, so write it with `jsonencode` and use the type the feature expects. Wayfinder converts some values to the declared type, for example the string `"false"` to the bool `false`. When that happens apply fails and names the `jsonencode(...)` value to use, so your configuration matches what Wayfinder stores.

## Destroying

Destroy disables the feature. The integration object stays in Wayfinder, and enabling it again later keeps its stored settings.

To leave a feature on when the configuration is destroyed, set `keep_enabled_on_destroy = true` and apply that change before you run destroy. Destroy reads the value from state, so setting it in the same run has no effect.

To stop managing one feature without disabling it, remove the resource and add a `removed` block:

```terraform
removed {
  from = wayfinder_feature_integration.azure

  lifecycle {
    destroy = false
  }
}
```

The always-on features `dns`, `kubernetes` and `terraform` can't be disabled. Destroying one of them removes it from state with a warning and leaves it enabled.

## Example Usage

```terraform
# Copyright 2026 Appvia Ltd.
# SPDX-License-Identifier: Apache-2.0

# Enable the Azure feature with its default settings.
resource "wayfinder_feature_integration" "azure" {
  name = "azure"
}

# Enable the AI feature with a parameter. Values are JSON, so use jsonencode
# with the type the feature expects (a bool here, not the string "false").
resource "wayfinder_feature_integration" "ai" {
  name = "ai"
  params = {
    enable_wayfinder = jsonencode(false)
  }
}

# Resources that need the feature should depend on it.
resource "wayfinder_azure_subscription" "dev" {
  # ...

  depends_on = [wayfinder_feature_integration.azure]
}

# Other teams rely on GitHub, so destroying this configuration leaves it on.
# Apply this setting before you run destroy.
resource "wayfinder_feature_integration" "github" {
  name                    = "github"
  keep_enabled_on_destroy = true
}
```

## Schema

### Required

- `name` (String) Bare feature name, for example `azure`, not `wayfinder.azure`.

### Optional

- `keep_enabled_on_destroy` (Boolean) Destroy disables the feature by default. Set to true to leave it enabled, and apply this value before destroying. A `removed` block with `lifecycle { destroy = false }` can also drop one resource from state without disabling it.
- `params` (Map of String) Feature parameters as JSON-encoded values, for example `enable_wayfinder = jsonencode(false)`. Only keys set here are managed; removing a key deletes it in Wayfinder. Use the JSON type the feature expects. For a JSON null, use `jsonencode(null)`; Terraform null map elements are not accepted.

### Read-Only

- `enabled` (Boolean) Whether the feature is enabled in Wayfinder.
- `id` (String) Integration object name, in the form `wayfinder.<name>`.
- `type` (String) Integration type reported by Wayfinder (`feature`).

## Import

The import ID is the bare feature name or the `wayfinder.<name>` object name. Only an enabled feature can be imported. Import doesn't adopt existing parameters, so `params` starts empty and only the keys you then add are managed.

```shell
#!/bin/sh
# Copyright 2026 Appvia Ltd.
# SPDX-License-Identifier: Apache-2.0

set -eu
# Either the bare feature name or the wayfinder.<name> object name.
terraform import wayfinder_feature_integration.azure azure
terraform import wayfinder_feature_integration.github wayfinder.github
```
