# wayfinder_invite (Resource)

Invite is an invitation for someone to join a tenant, addressed to an email address and carrying the roles and workspace memberships they will be granted when they accept. The invitation link is emailed to them and is valid until the invite expires; revoking an invite means deleting it.

}

## Schema

### Required

- `email` (String) Email is the email address the invitation is sent to, e.g. "alex@acme.com".
- `invited_by` (String) InvitedBy is the username of the person who created the invite.
- `name` (String)
- `roles` (List of String) Roles are the names of the Wayfinder roles granted when the invite is accepted. At least one is required, e.g. ["tenant.member"].

### Optional

- `annotations` (Map of String)
- `auto_join` (Boolean) AutoJoin indicates the person was admitted automatically because their email domain is allowed for this tenant, rather than being invited by name. Set by Wayfinder.
- `expires_at` (String) ExpiresAt is when the invitation stops being usable. After this point the invite reads as expired and a new one must be sent.
- `labels` (Map of String)
- `message` (String) Message is an optional personal note included in the invitation email.
- `scope` (String) Scope is how far the granted access reaches. Only tenant owners and admins can create invites.
- `tenant` (String) Tenant is the tenant the invite belongs to. It is filled in only when invites are listed across tenants, for example when showing someone every invitation waiting for them, and is empty otherwise.
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `token_id` (String) TokenID identifies the invitation link that is currently valid. The link itself is only ever emailed to the invited person and is never stored, so it cannot be retrieved; resending the invite issues a new link and invalidates the previous one.
- `wait_for_ready` (Boolean)
- `workspace_roles` (Attributes List) WorkspaceRoles are workspace-scoped roles granted when the invite is accepted, each entry naming one workspace and the roles granted in it, e.g. workspace "team-a" with role "workspace.member". Use this to invite someone straight into a workspace instead of granting them access afterwards. (see [below for nested schema](#nestedatt--workspace_roles))
- `workspaces` (List of String) Workspaces are the names of the workspaces to add the invited person to. They are added to each named workspace's members group on acceptance.
