# wayfinder_manifest (Resource)

Manages one Wayfinder object from a YAML or JSON manifest. Use it for kinds without a dedicated resource. Only the fields set in the manifest are managed. Secret fields are set through the write-only manifest_wo attribute and are never stored in state.

The `manifest` attribute holds one Wayfinder object as YAML or JSON, in the same shape the `wf` CLI applies: `apiVersion`, `kind`, `metadata` and `spec`. Only the fields you set are managed. Fields that Wayfinder or other tools add are left alone, and labels and annotations you don't set are kept.

The text can come from `file()` or `templatefile()`. To write an object inline, build it with `yamlencode()` as in the example below.

Use `wayfinder_manifest` for kinds that have no dedicated resource, or when you'd rather keep an object in its YAML form. Changing `kind`, `metadata.name`, `metadata.workspace`, `metadata.environment` or `metadata.version` replaces the object.

Kinds that record activity (runs, invocations and conversations) or that Wayfinder manages itself (tenants, users and identities, for example) can't be managed by Terraform, and a manifest for one is rejected at plan time. Use `wayfinder_variable` and `wayfinder_secret` for variables and secrets.

## Secrets

Put secret fields in `manifest_wo`. It's a write-only attribute that takes YAML or JSON and is merged into `manifest` before the object is sent. Its value is never stored in the plan or in state. Write-only attributes need Terraform or OpenTofu 1.11 or later. Pass secret values in through variables, ideally ephemeral ones, rather than writing them as literals in your configuration, because Terraform can show the related configuration lines in error output.

The merge works like this:

- Objects merge by key.
- Lists merge item by item. The list in `manifest_wo` must have the same length as the one in `manifest`, with `null` for items it doesn't change.
- `manifest_wo` can't set `apiVersion`, `kind`, `metadata` or `status`.
- A field can appear in both attributes only when it's a secret field and `manifest` holds a blank placeholder for it.

Everything in `manifest_wo` is sent when the object is created or replaced. After that, Terraform can't see changes to `manifest_wo`, so changing it alone sends nothing. To send a value again, add or change its entry in `manifest_wo_version`, a map from field path to a version string, as in the example below. Only the paths whose version changed are sent.

Removing a value from `manifest_wo` doesn't delete it in Wayfinder.

Secret fields the provider knows about are rejected at plan time when they're set in `manifest`. Any other value you'd rather keep out of state can go in `manifest_wo` too.

## Example Usage

```terraform
resource "wayfinder_manifest" "developers" {
  manifest = yamlencode({
    apiVersion = "org/v3"
    kind       = "Group"
    metadata = {
      name = "developers"
    }
    spec = {
      description = "Development team members"
      members = [
        {
          kind = "User"
          name = "alice@example.com"
        },
      ]
    }
  })
}

variable "webhook_secret" {
  type      = string
  sensitive = true
  ephemeral = true
}

resource "wayfinder_manifest" "github_webhook" {
  manifest = yamlencode({
    apiVersion = "integrations/v3"
    kind       = "Webhook"
    metadata   = { name = "github", workspace = "plat" }
    spec = {
      integrationRef = "github"
      security       = { algorithm = "hmac-sha256", signatureHeader = "X-Hub-Signature-256" }
    }
  })
  manifest_wo = yamlencode({
    spec = { security = { secret = var.webhook_secret } } # never stored in state
  })
  manifest_wo_version = {
    "spec.security.secret" = "1" # bump to send a new secret
  }
}
```

All of it is sent when the object is created or replaced; after that, only paths listed in manifest_wo_version are sent, when their version is added or changed. - `manifest_wo_version` (Map of String) Versions of paths in manifest_wo. Each key is a path such as spec.security.secret, spec.rules[0].token or spec.headers["X-Api-Key"]; a path to an object or list covers everything beneath it. ## Import

The import ID is `<group>/<Kind>/[workspace/[environment/]]name[@version]`, where `<group>` is the API group from `apiVersion` without the version, for example `org/Group/developers` or `core/Environment/plat/dev`.

```shell
#!/bin/sh
set -eu
# <group>/<Kind>/[workspace/[environment/]]name[@version]
terraform import wayfinder_manifest.developers 'org/Group/developers'
```

After importing, set `manifest` to the fields you want Terraform to manage.

After importing, set manifest_wo and manifest_wo_version; secrets are sent on the next apply for each version key you add.
