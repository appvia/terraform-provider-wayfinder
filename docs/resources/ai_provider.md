# wayfinder_ai_provider (Resource)

AIProvider declares where inference comes from, which models it can run, and what they cost. One provider is one place plus the key that opens it: a dialect (the wire format), a backend (the transport and credential) and a catalogue of models under portable names.

Wayfinder ships system-scoped providers, referenced as "wayfinder/NAME"; tenants may define their own at tenant, workspace or environment scope. An AIAgent selects one model at one provider through an AIModelRef such as "wayfinder/anthropic:haiku-4.5".

## Example Usage

```terraform
// Code generated by tfgen. DO NOT EDIT.
resource "wayfinder_ai_provider" "example" {
  name = "example"
  workspace = "example"
  backend = {
    type = "direct"
  }
  dialect = "anthropic"
  models = [{
    id = "example"
    name = "example"
  }]
}
```

### Nested Schema for `backend`

Required:

- `type` (String) Type is the transport used to reach the provider.

- `direct`: Reaches the provider over plain HTTPS at its own base URL, authenticating with the headers its ExternalIdentity carries. This covers the vendor's own API and any gateway that fronts it — OpenRouter, LiteLLM, Azure API Management.

- `bedrock`: Reaches the provider through AWS Bedrock, signing requests with SigV4.

- `vertex`: Reaches the provider through Google Vertex AI.

- `foundry`: Reaches the provider through Azure Foundry.

Optional:

- `base_url` (String) BaseURL is the endpoint to send requests to, for a "direct" backend. Leave it unset to use the dialect's own public API; set it to route through a gateway such as OpenRouter, LiteLLM or Azure API Management. It is ignored by the bedrock, vertex and foundry backends, which derive their own endpoints.

Give the whole prefix the endpoint expects, version segment included — "https://openrouter.ai/api/v1" rather than "https://openrouter.ai". The dialect appends only its own operation path to it.

Note that this field decides where conversation content is sent, so the permission to set it below tenant scope is granted rather than assumed.
- `extra_body_json` (String) ExtraBody is merged into the JSON body of every request to this provider, for endpoints that need a field Wayfinder does not otherwise send. Its keys are the wire names the endpoint expects, and they overwrite anything Wayfinder set under the same name.

This is the escape hatch for an endpoint with its own requirements — a vendor-specific toggle, a routing hint, a sampling parameter — so that reaching one does not wait on Wayfinder adding a field for it. Nothing validates the contents beyond their being a JSON object: an endpoint that dislikes what you send will say so.
- `headers` (Map of String) Headers are extra non-secret HTTP headers sent with every request, for gateways that want attribution or routing hints — OpenRouter's HTTP-Referer, for instance. Secret values belong in the ExternalIdentity named by Identity, never here: these are stored and returned in clear.
- `identity` (String) Identity is the ExternalIdentity holding the credential presented to the provider — a BearerToken for an API key, an APIKey for gateways that want a named header such as Azure API Management's Ocp-Apim-Subscription-Key, or a cloud identity for the bedrock, vertex and foundry backends.

The reserved value "ambient" means Wayfinder's own cloud credentials and is valid only on a system-scoped provider.
- `max_tokens_field` (String) MaxTokensField names the request field this endpoint expects the output limit in. OpenAI-compatible servers disagree: the current field is maxCompletionTokens, which is the default here, but self-hosted runtimes and older gateways often accept only the original maxTokens and reject a request carrying the newer name.

Set it if the endpoint rejects requests with an unknown-field error mentioning max_completion_tokens. Applies to the openai dialect only.

- `maxCompletionTokens`: Sends the limit as max_completion_tokens, which current OpenAI-compatible endpoints expect.

- `maxTokens`: Sends the limit as max_tokens, the original field, which some self-hosted runtimes and older gateways require.
- `region` (String) Region is the cloud region for the bedrock and vertex backends, e.g. "us-east-1" or "europe-west4".
- `resource` (String) Resource is the Azure Foundry resource name, used to build its endpoint, e.g. "acme-ai-foundry".

### Nested Schema for `models`

Required:

- `id` (String) ID is the model identifier this provider's backend expects: a vendor model name, a Bedrock inference-profile ARN, an Azure Foundry deployment name, or a gateway slug such as "anthropic/claude-sonnet-4.5". Unlike Name it is free-form, because upstream identifiers routinely contain characters — slashes especially — that a reference grammar cannot carry.
- `name` (String) Name is the portable name an AIAgent references, as the part after the ":" in an AIModelRef — "haiku-4.5" in "wayfinder/anthropic:haiku-4.5". Keep it the same across providers offering the same model so retargeting is a one-word change.

Optional:

- `cache_creation_weight` (Number) CacheCreationWeight is the cost of one token written to the provider's prompt cache, in Cost.Unit.
- `cache_read_weight` (Number) CacheReadWeight is the cost of one token read from the provider's prompt cache, in Cost.Unit.
- `context_window` (Number) ContextWindow is the total number of tokens this model can consider at once, covering the conversation so far and the reply it is about to make. It is recorded for display and comparison — Wayfinder does not trim a conversation to fit it.
- `display_name` (String) DisplayName is the human-readable model name shown in the UI.
- `input_weight` (Number) InputWeight is the cost of one input token, in Cost.Unit. Weights are per single token, so a model charged one credit per input token carries 1 here.
- `max_tokens` (Number) MaxTokens is the largest number of tokens this model may generate in one reply. Set it to what the model actually supports: capacity varies by orders of magnitude between models, and a conversation that hits the limit is cut off mid-answer.

Left unset, a conservative default is applied, which for a large model wastes most of its capacity. An agent can still ask for less through its modelParameters, but it cannot exceed what the model can do, so this is the right place to record it.
- `output_weight` (Number) OutputWeight is the cost of one output token, in Cost.Unit.
- `thinking` (Attributes) Thinking records how this model is asked to reason, so an agent can name an effort level without knowing which of the several ways to request it this particular model expects.

Leave it unset for a model that does no reasoning, or where the default behaviour is wanted and never varied. (see [below for nested schema](#nestedatt--models--thinking))

### Nested Schema for `models.thinking`

Required:

- `mode` (String) Mode is how this model is asked to reason. Getting it wrong is not a degraded result but a rejected request: a model configured by token budget refuses a request naming an effort level, and a current model refuses a token budget.

- `effort`: Asks for reasoning by naming a level, which is how current models are configured.

- `budget`: Asks for reasoning by giving a number of tokens to spend on it, which is how older models are configured. Those models reject a request that names a level instead, so the two are not interchangeable.

- `always`: Describes a model that always reasons and cannot be asked not to. Effort still selects how deeply.

Optional:

- `budgets` (Map of Number) Budgets maps each effort level onto the number of thinking tokens to ask for, for a model in budget mode. A level with no entry falls back to the nearest lower level that has one.
- `default` (String) Default is the effort used when an agent names none.

- `none`: Answers directly, without reasoning first.

- `low`: Does a little reasoning — for short, scoped tasks where speed matters more than depth.

- `medium`: Balances reasoning depth against time and cost.

- `high`: Reasons thoroughly — the right default for work where the answer's quality matters.

- `xhigh`: Reasons harder than high, for demanding coding and agentic work on models that offer the level.

- `max`: Reasons as deeply as the model can, for problems where correctness matters more than what it costs.
